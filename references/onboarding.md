# 用户引导话术与场景决策（onboarding）

> 本文件供 AI 在引导用户时参考。原则：**优先推送交互卡片，一次只问一组问题、用选项代替开放提问、主动推荐而非让用户猜**。

## 第一步：推送交互卡片（推荐，体验最优）

用户提出证件照需求后，**优先推送一张可勾选的飞书交互卡片**（环境支持 lark-im 时）：

- **卡片模板**：`references/idphoto-card.json`（Card 2.0，含表单）
- **卡片内容**：
  - 一键换底（**单选**，select_static 下拉）：蓝（默认）/ 红 / 白
  - 是否换正装（checker 勾选，默认勾选：深色西装+白衬衫）
  - 确认按钮（form submit）
- **发送方式**（lark-im）：
  ```bash
  lark-cli im +messages-send --chat-id <oc_xxx> --msg-type interactive --content '<idphoto-card.json 的内容>'
  ```
- **读取用户选择**：用户点「确认」后，从回调 `action.form_value` 读取：
  - `bg` = `blue` / `red` / `white`（单选，只有一种底色）
  - `suit` = true / false（是否换正装）
  - 若回调不可达，请用户把选择以文字发来（卡片底部已提示）。

### 卡片回调的飞书侧配置（一次性）
要让「确认」按钮的选择结果回到 AI，需在**飞书开放平台后台**配置（需应用管理员权限，lark-cli 无法代做）：
1. 打开[飞书开放平台](https://open.feishu.cn) → 进入该应用
2. 应用能力 → **机器人** → 事件与回调 → **事件订阅**
3. 确认已配置「**卡片行为回调**」事件（card.action.trigger / 卡片按钮回调）
4. 配置**请求网址（回调地址）**：填写接收卡片回调的 http 服务地址（由运行豆包/机器人的平台方提供）
5. 启用事件后，用户点卡片「确认」，飞书会 POST 回调到该地址，AI 即可读取勾选结果
> 若暂无法配置，走**文字兜底**（见下），流程依然完整。

### 回调不可用时的文字兜底
若环境不支持卡片回调，退化为**文字选项列表**，让用户回复选择（换底单选）：
```
请选择你的需求（直接回复即可）：
🟦 一键换底：红色 / 白色 / 蓝色（三选一）
👔 是否换正装：是 / 否
（例：回复「红底+换正装」）
```

## 第二步：收集输入（按序确认，每轮最多 2~3 项）

1. **照片**：请用户上传**正面、单人、光线均匀**的人像照；没给就先索要，并提示要求（避免多人/侧脸/逆光）。
2. **换装**：以卡片勾选为准——勾了 `suit` → 需要一键换正装；未勾 → 跳过。
3. **底色与尺寸**：以卡片勾选为准（红/白/蓝）；尺寸默认一寸（295×413），用户有特殊规格再调整。
4. **排版照**：是否需要 6 寸排版照（可直接冲印）。

## 底色 × 用途推荐表

| 场景 | 推荐底色 | 说明 |
| --- | --- | --- |
| 求职 / 入职 / 简历 / 工作证 | 蓝底 | 最常用 |
| 考试报名 / 证书 / 社保 | 红底 | 具体以报名要求为准 |
| 签证 / 护照 / 身份证件类 | 白底 | 多数证件照规范 |
| 不确定 | 蓝底（默认） | 蓝底普适性最强 |

## 第三步：执行并展示

- 环境未初始化 → 先跑 `scripts/setup.sh`（幂等）。
- 换装（勾选 suit）→ 先执行换装（见 `dressing.md`），再跑 `pipeline.py`。
- 生成后**直接向用户展示图片**（优先拼一张「效果一览」大图：原图→换装→证件照→排版照，一眼看全），并说明可再调整。

## 第四步：迭代确认（话术模板）

> 「做好啦，你看下效果～ 需要的话我可以帮你：
> - 换个底色（红/蓝/白）
> - 换成二寸/其他尺寸
> - 换套西装样式
> - 出一张六寸排版照
> 直接告诉我要调哪个就行。」

## 边界与提示

- 证件照需**单人正面照**：多人、侧脸、低头、逆光会失败，提前提醒用户。
- 换装只替换服装、**必须保持人脸/发型一致**（见 `dressing.md`）。
- 不主动编造用户未提供的用途信息；不确定时用选项问，而不是假设。
